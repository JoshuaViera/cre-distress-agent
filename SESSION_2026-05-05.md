## 6. Tier 2 — Snapshot persistence + real diff logic

Goal of Tier 2: ship the daily-diff capability from Wave 2 ADR-001 §4 ("Done by end of Wednesday"). Three commits, each independently revertable.

### 6.1 Tier 2a — Atomic snapshot writer + reordered `_gather_signals`
**Commit:** `9a31272` — `feat(agent): add atomic snapshot writer + reorder _gather_signals`

- **What:**
  - New `SNAPSHOTS_DIR = REPO_ROOT / "snapshots"` constant in `agent.py`.
  - New `_write_snapshot(deal_id, tool_outputs)` function: creates `snapshots/{deal_id}/`, writes to `{YYYY-MM-DD}.json.tmp`, then `os.replace` for atomic rename. Same-date runs overwrite (filename is the UTC date).
  - Snapshot payload schema (locked):
    ```json
    {
      "snapshot_version": "v2",
      "captured_at": "<ISO 8601 UTC>",
      "deal_id": "<from deal profile>",
      "tool_outputs": {
        "violations": <parsed JSON from violations tool>,
        "market_signals": <parsed JSON>,
        "macro_signals": <parsed JSON>,
        "underwriting": <parsed JSON>
      }
    }
    ```
  - Reordered `_gather_signals`: removed the early stub call between FRED and underwriting; the snapshot is now written AFTER underwriting (so it captures all four tool outputs), then the diff is called against the freshly-written file.
  - `snapshots/` added to `.gitignore`.
- **Why:**
  - **Snapshots contain only ground-truth observations**, NOT the LLM's phase-1 scoring. Reasoning: scoring logic will change (model swap to Claude, possibly Greg's IRR-threshold dispatch); snapshots that include scoring become noise. Day-over-day diffs need to reflect actual world changes, not changes in how we interpret the world.
  - **Atomic write via `os.replace`** is cross-platform (POSIX + Windows). Without atomicity, a crash mid-write could leave a corrupt JSON file that breaks the diff loader on subsequent runs.
  - **Filename is the date, same-date overwrites:** matches the ADR-001 contract — "If two runs occur on the same date, the latest one wins." Multiple runs on a single day are normal during development; we don't want one snapshot per run.
  - **Diff after write:** the diff function reads both today's and yesterday's from disk. By writing first, the diff function only needs `deal_id` as input — no need to plumb in-memory tool outputs through.
- **Files:** `.gitignore`, `agent.py`
- **Verification:** Smoke test wrote a synthetic snapshot to `snapshots/test-smoke-deal-DELETE-ME/2026-05-05.json`, verified all fields, cleaned up.
- **Behavior change in this commit:** Stub still active; the diff result is still empty. But snapshots will now appear on `agent.py` runs.

### 6.2 Tier 2b — Real diff logic
**Commit:** `6beea39` — `feat(snapshot_diff): replace stub with real day-over-day diff`

- **What:** Rewrote `tools/snapshot_diff.py`:
  - `compare_to_yesterday(deal_id, snapshots_dir=None) -> str`:
    - Lists snapshot files under `snapshots/{deal_id}/`, filters to filenames matching `YYYY-MM-DD`, sorts descending, removes today's date, takes the next.
    - If no prior snapshot → returns `{no_change: true, compared_against: null, note: "no prior snapshot — first run for this deal_id"}`.
    - Else loads today's + prior snapshots, walks both `tool_outputs` trees recursively, emits field-level diffs.
  - **Diff output format** (locked):
    ```json
    {
      "deal_id": "...",
      "diff_summary": [
        {"field": "tool_outputs.macro_signals.treasury_10y.bps_change", "yesterday": 25, "today": 30, "delta": 5}
      ],
      "new_signals": [],
      "dropped_signals": [],
      "no_change": false,
      "compared_against": "2026-05-04"
    }
    ```
  - **Diffable fields:** numeric leaves (int/float, excluding bool) AND three signal-state categoricals (`market_signal`, `macro_signal`, `distress_score`).
  - **Skipped fields** (in `SKIP_KEYS`): source URLs (`source_url`, `source_url_treasury_10y`, `source_url_sofr`), free text (`narrative`, `message`), sample lists (`sample_violations`, `sample_sales`, `drivers`, `narrative_inputs`), per-run timestamps (`most_recent_violation`, `captured_at`), snapshot metadata (`snapshot_version`, `deal_id`, `assumptions_locked_at`), deal-constant identifiers (`bbl`, `borough`, `borough_code`), legacy stub flag (`stub`).
  - **`new_signals` / `dropped_signals`:** detected at the top-level `tool_outputs` keys. If a fifth tool gets added later, today's snapshot will have a top-level key absent in yesterday's → that key shows up in `new_signals` for one day.
  - **Generic walker** (`_walk_diff(today, yesterday, prefix)`): recursive, handles arbitrary nesting, follows path semantics (`tool_outputs.macro_signals.treasury_10y.bps_change`). Adding a new tool requires zero changes here.
  - **`__main__` smoke test:** four scenarios via synthetic snapshots in a `tempfile.TemporaryDirectory`:
    1. No prior snapshot → empty envelope with note
    2. Real diff: numeric changes (+2 violations, +20 bps, +0.25 treasury), categorical changes (`distress_score` medium→high, `macro_signal` stable→rates_moved), structural change (new `market_signals` tool)
    3. Noisy fields (URLs, timestamps, samples) correctly skipped
    4. Identical snapshots → `no_change=true` with prior date echoed
- **Why:**
  - **Generic walker over hardcoded paths:** ADR-001 §6 contract 2 explicitly says snapshots/diff schema must support adding tools without rewriting diff code. The walker delivers that.
  - **Skip noisy fields:** `most_recent_violation` moves every time HPD adds any new violation (irrelevant for our purposes); `source_url` may have query params that drift; `narrative` is LLM-generated free text that drifts every run. Diffing them creates pure noise that drowns out real signals.
  - **Surface only numeric + signal-state categoricals:** these are the fields the analyst actually cares about ("did the rate move", "did the market signal change"). Adding more categorical whitelist entries is a one-line change to `SIGNAL_STATE_KEYS`.
  - **`snapshots_dir` kwarg:** lets the `__main__` test point at a tempdir without polluting the real `snapshots/`. Production always uses the default.
- **Files:** `tools/snapshot_diff.py` (full rewrite, 313 lines including the test)
- **Verification:** All 4 smoke tests pass.
- **Behavior change at this point in history:** snapshots written by 2a are now actually being diffed. But the diff result still isn't shown to the model — that's 2c.

### 6.3 Tier 2c — Render diff into `_signals_block`
**Commit:** `aa42536` — `feat(agent): render snapshot diff into _signals_block for phase 1`

- **What:** New helper `_render_snapshot_diff(diff)` in `agent.py` with three render modes, called from `_signals_block`:
  - **First run (no prior snapshot):** one-line note: `"TOOL OUTPUT — Snapshot diff vs prior snapshot\n(No prior snapshot for this deal_id; this is the first run. Diff context not yet available.)"`
